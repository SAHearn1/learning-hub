# Compliance Audit Evidence Matrix

This matrix maps key controls to auditable evidence generated by the platform and operational process.

| Control objective | Implementation baseline | Evidence artifact | Cadence | Owner |
| --- | --- | --- | --- | --- |
| Minor consent enforcement | API-level consent gating before learning workflows | `CONSENT_STATUS_UPDATED` audit entries + denied access logs | Continuous + monthly spot check | Privacy + Engineering |
| Data-rights request intake | `/api/compliance/data-rights` workflow with role checks and audit log write | `DATA_RIGHTS_REQUESTED` audit entries and request ticket linkage | Continuous + weekly review | Privacy Ops |
| Audit trail integrity | Structured API logging with request IDs and centralized audit log model | Exported log snapshots correlated by `X-Request-Id` | Daily | Security |
| Incident readiness | Documented incident playbook and post-incident template | Incident tickets, timeline notes, remediation checklist | Quarterly tabletop | Security + Compliance |
| Production observability baseline | Metrics endpoint and latency/error counters | `/api/metrics` snapshots and alert records | 5-minute collection, weekly review | SRE/Platform |
| Billing lifecycle traceability | Stripe checkout/portal/webhook route instrumentation | Subscription lifecycle events and support audit records | Continuous + monthly reconciliation | Finance Ops + Engineering |

## Minimum monthly evidence packet
1. Exported audit events for consent updates and data-rights requests.
2. Metrics snapshot showing API error/latency posture.
3. Stripe subscription lifecycle reconciliation report.
4. Any incident tickets opened/closed and associated postmortem status.
